# Changelog

## 1.1.0 — 2026-09-05

Stable release promoted after live Gamemaster and player-account validation.

- Added optional **Portable (World)** breach puzzles for stolen laptops, carried devices, recurring props, and other mobile breach targets while keeping Scene-local storage as the default.
- Preserved existing v1.0.5 Scene-local puzzles and bindings without forced migration.
- Added confirmed Scene-local ↔ Portable conversion with binding cleanup/migration and reward-claim migration.
- Portable Tile bindings remain valid when copied/duplicated across Scenes when their flags are preserved; deleting a Portable puzzle removes its portable bindings across all Scenes.
- Every live breach attempt now receives one fresh runtime-randomized matrix; the GM matrix is a preview/sample, and Emergency Reset randomizes again.
- Added GM-authoritative **one-time reward claims** to stop repeated loot farming, plus per-sequence **Repeatable payload** and GM **Reset Reward Claims** controls.
- GM Preview remains non-destructive and neither grants nor consumes rewards.
- Restored the proven v1.0.5 player matrix interaction architecture after beta testing: click → validate → update path/buffer → detect sequences → normal Foundry render. Reward/socket bookkeeping remains outside the path-selection loop.
- Enabled Foundry package sockets with `"socket": true` so player-account reward requests reliably reach an active GM. Reward requests include Actor UUID and Actor ID, with GM-side Actor fallback resolution.
- Confirmed live player-account Item reward delivery to the Cyberpunk RED Actor sheet.
- Preserved Netrunner-only live access, explicit `success` / `partial` / `failure` / `aborted` outcomes, and CitiNet/companion-module close-hook metadata including puzzle scope and Scene ID.
- Added GitHub-oriented Quick Start, Portable workflow, install/upgrade guidance, API examples, and troubleshooting documentation.

## 1.1.0-beta.6 — 2026-09-05

- Fixed player-account Item/Eurobuck/data reward delivery introduced by the GM-authoritative one-time reward system.
- Added `"socket": true` to `module.json`, which requests Foundry's `module.hexcode-breach-lite` package socket namespace so reward requests are actually relayed between player and GM clients.
- Added `actorId` alongside `actorUuid` to reward requests and a GM-side world-Actor fallback when UUID resolution is unavailable.
- GM-side reward writes now allow GM authority directly instead of requiring the target Actor's client-facing `isOwner` flag.
- Kept reward settlement outside the matrix path-selection loop; no beta.5 gameplay-loop behavior was changed.
- A full Foundry restart is required after installing this build because the socket namespace is declared by the package manifest at startup.
- No puzzle, binding, storage, or reward-claim migration is required from beta.5.

## 1.1.0-beta.5 — 2026-09-05

- Rolled the player matrix interaction engine back to the proven v1.0.5 architecture instead of continuing to patch beta.2–beta.4 UI/race symptoms.
- Removed the beta.3 click Promise queue and beta.4 direct matrix-DOM synchronization/disabled-cell gate.
- Each breach now receives one finalized runtime puzzle snapshot before the player Application begins rendering; the fresh randomized matrix is generated once per attempt and is not regenerated by `getData()` or later renders.
- Matrix selection is again a simple Foundry click → `isAllowed()` validation → buffer/path update → synchronous sequence detection → normal Application render.
- GM-authoritative one-time reward verification and chat posting now settle asynchronously after a sequence is marked cracked, so network/chat latency cannot block or reorder the next legal row/column selection.
- Sequence crack chat is posted immediately; payload settlement is posted separately when the GM-authoritative reward result returns.
- Portable storage, saved-puzzle scope conversion, binding migration/cleanup, fresh matrices, repeatable payloads, reward-claim reset, Netrunner enforcement, and CitiNet outcome metadata are unchanged.
- No puzzle, binding, storage, or reward-claim migration is required from beta.4.

## 1.1.0-beta.4 — 2026-09-05

- Hardened the player matrix against stale cyan-path UI after beta.3 live testing.
- The visible matrix route is now synchronized directly in the current DOM immediately after every accepted selection instead of relying on Foundry's asynchronous Application rerender to catch up.
- Cells outside the authoritative legal route are disabled and cannot enter the matrix click queue; stale/invalid UI clicks are ignored instead of generating a misleading `Invalid breach path` warning.
- Buffer slots update synchronously with the same path state, while the normal render still refreshes solved-sequence/reward presentation after asynchronous work completes.
- No puzzle, binding, reward-claim, or storage migration is required from beta.3.

## 1.1.0-beta.3 — 2026-09-05

- Fixed a matrix input race where a correct next row/column selection could be rejected as **Invalid breach path** while the previous click was still waiting on asynchronous chat or GM-authoritative reward verification.
- Matrix clicks are now serialized in input order, so rapid player clicks cannot overtake one another.
- The first selected hex now advances timer/path state immediately; breach-start chat posting no longer blocks that state change.
- The matrix re-renders immediately after each accepted selection, before reward/chat settlement, keeping cyan allowed-cell highlighting synchronized with the authoritative path validator.
- No puzzle, binding, reward-claim, or storage migration is required from beta.2.

## 1.1.0-beta.2 — 2026-09-05

- Fixed saved-puzzle Storage Scope conversion. A loaded puzzle now keeps its persisted scope separate from its pending target scope until Save confirms the move.
- Added an explicit confirmation when moving Scene-local → Portable or Portable → Scene-local; one-time reward claims migrate with the puzzle.
- Every live breach attempt now receives a fresh runtime-generated matrix. The matrix saved in GM Config is a preview/sample; Emergency Reset still rebuilds it again.
- Added GM-authoritative one-time reward claims to prevent repeatedly reopening the same breach for duplicate Eurobucks, Items, or RollTable data.
- Added a per-sequence **Repeatable payload** option for intentionally reusable rewards/data. Existing sequences default to one-time rewards.
- GM Preview is now non-destructive for rewards: it neither grants payloads nor consumes one-time claims.
- Added **Reset Reward Claims** and claim counters to the GM editor for deliberate re-arming/testing.
- Portable reward claims follow the puzzle across Scenes; Scene-local claims remain tied to their Scene. Deleting a puzzle also cleans its stored claims.
- Added `sceneId` to the `closeHBLPlayerApp` result payload.
- Kept v1.0.5 compatibility: existing puzzles normalize cleanly and old Tile bindings remain Scene-local unless explicitly moved.

## 1.1.0-beta.1 — 2026-09-05

- Added **Portable (World)** breach puzzles for laptops, carried devices, recurring props, and other breaches that need to move between Scenes.

- Reworked README into a GitHub-oriented Quick Start with portable-device workflow, install/update guidance, troubleshooting, rules, API, and hook documentation.

## 1.0.5 — 2026-08-28

Verification candidate for the CitiNet/companion-module close-hook integration.

- Added explicit player-run outcomes: `success`, `partial`, `failure`, and `aborted`.
- Cracking one or more but not all sequences is now reported as **partial success**; cracking every sequence is **full success**. The established rule that one cracked sequence secures its payload/reward remains unchanged.
- Manual close after securing at least one sequence reports `partial`; manual close before securing a sequence reports `aborted`.
- `closeHBLPlayerApp` now fires after `super.close()` completes rather than before the Foundry window closes.
- The hook still passes the app instance first for compatibility and now passes a second `resultData` argument containing outcome, reason, puzzle/actor identifiers, solved counts/IDs, and GM-preview state.
- Added a one-shot guard so the close hook cannot fire twice for the same player app instance.
- Added `relationships.systems` for `cyberpunk-red-core` with minimum/verified `0.92.1`, plus a recommendation for Monk's Active Tile Triggers.
- Synchronized the manifest and README to v1.0.5 verification-candidate status.
- No puzzle-data or Tile-binding migration is required.

## 1.0.3 — 2026-08-11

Stable Monk's Active Tile Triggers helper compatibility repair.

- The generated helper no longer depends on the `game.hexcodebreach` compatibility alias.
- The helper now calls `game.modules.get("hexcode-breach-lite").api.openBound(...)` directly, matching the proven helper pattern used by the user's other Foundry modules.

- Retains `game.hexcodebreach` only as a backwards-compatibility alias.
- If an older helper Macro is already malformed, delete it once and recreate it from the GM Config window.
- No puzzle-data or Tile-binding migration is required.
